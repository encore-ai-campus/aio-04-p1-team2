# Sea-Info 코드 구조와 작업 기준

기준 경로: `C:\svn\sea_info` / 확인일: 2026-11-12

이 문서는 소스 구조와 기능 간 연결을 정리한다. 전체 기능의 운영 검증 완료를 의미하지 않는다. 기존 실행 검증 결과는 별도 Supabase·Jira 검증 보고서와 수족관 완료 화면 보고서를 참조한다.

## 실행과 계층

`start.bat`은 Python 3.13 가상환경, 포트 충돌, 의존성, 환경 파일, Redis와 서버 실행을 관리한다. 기본 API 포트는 8005이며 API_PORT로 변경할 수 있다. 실제 화면의 API 주소는 실행 환경의 BACKEND_URL을 기준으로 한다.

사용자 요청은 대체로 `app.py → components/nav.py → views → services → services/api.py → backend/routers → SQLModel/Redis/외부 서비스` 순으로 흐른다. `backend/main.py`는 라우터 모듈을 자동 등록하고 수명주기에서 DB 초기 점검을 수행한다. 라우터 import 실패는 로그에 남기고 나머지 등록을 계속하므로 서버 기동만으로 모든 API의 정상 등록을 보장하지 않는다.

## 데이터·권한 경계

- 앱 데이터 DB는 `DATABASE_URL`로 선택한다. PostgreSQL 연결은 `DATABASE_SCHEMA`로 스키마를 지정한다. PostgreSQL 시작 시 테이블을 자동 생성하거나 예시 데이터를 넣지 않고 존재 여부를 확인한다. SQLite와 예시 데이터는 별도 로컬 경로다.
- Supabase Auth 로그인과 PostgreSQL 앱 데이터 저장은 서로 다른 설정과 처리 경로다. 로그인 연결 성공만으로 앱 DB 저장 성공을 판단하지 않는다.
- Redis는 로그인 세션, 인증용 임시 값, 사용량·랭킹·조회수 등에도 사용한다. DB만 연결되어도 모든 기능이 정상인 것은 아니다.
- 서버의 `require_user`, `require_admin`이 권한을 검사한다. 화면 메뉴 숨김만으로 접근을 제한하지 않는다. 사진은 photos 라우터의 접근 검사도 함께 확인해야 한다.
- 회원 탈퇴는 관련 데이터 재배정과 문의 연락처 제거 등 앱 데이터 처리를 포함한다. Supabase Auth 계정의 실제 삭제 여부는 별도 확인 대상이다.
- 서비스 계층 캐시와 Streamlit session_state가 있으므로 저장 성공 여부와 완료 화면 표시 여부를 각각 검증한다.

## 이미지 저장 흐름

분석 업로드, 분석 결과, 수족관 저장, 완료 화면을 구분한다. 분석 결과만 표시된 상태는 Observation 저장 완료가 아니다. 앞선 수정은 저장 성공 후 완료 상태를 우선 렌더링하도록 처리했다. 재실행·다시 누르기에서 중복 저장과 화면 상태도 함께 점검한다.

## 문의·Jira·메일: 현재 작업 상태

기존 구현에는 문의 DB 저장, Jira 이슈 생성·동기화, 답변이 있는 완료 문의의 메일 발송 경로가 있었다. 운영자에게 보내는 접수 알림과 제보자에게 보내는 진행 안내는 수신자와 목적이 다르다.

현재 작성 중인 확장 코드는 `inquiry_workflow_models.py`, `inquiry_workflow.py`, `inquiry_worker.py`, `core/notification_mail.py`와 연결 라우터·화면에 걸쳐 있다. 접수·처리 시작·완료 이벤트, 메일 대기열, Jira 폴링, 전송 실패·결과 불명 상태 및 재시도 제어를 다룬다. 연결된 문의 상태는 Jira에서 변경하고 공개 답변은 앱에서 관리하는 방향이다.

2026-11-12 재실행한 `tools.test_inquiry_notifications`는 **25건, 실패 0, 오류 0**이다. SQLite 테스트 DB와 모의 외부 연동을 사용한 결과로, Supabase 운영 반영이나 실제 SMTP 수신 성공을 입증하지 않는다.

**이 문서 작성 당시 상태(아래 후속 보고서 참조):** 새 테이블 `inquiry_event`, `inquiry_notification`, `inquiry_sync_state`의 Supabase 반영과 기존 문의 기준 상태 등록, 실제 Jira·메일 통합 검증이 남아 있다. 현재 시작 점검은 새 테이블도 요구하므로 테이블 반영 전 업데이트된 API를 재시작하면 누락 테이블 오류가 날 수 있다. 이 문서 작성 과정에서는 DB 변경·서버 재시작·실제 메일 발송을 수행하지 않았다.
